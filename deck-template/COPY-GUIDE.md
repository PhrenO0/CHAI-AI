# 카피 지침 — 슬라이드에 들어가는 말투

기획서 덱의 문장은 보고서 문장과 다르다. 발표자가 말할 것이고, 청중은 3초 안에 읽는다.
그리고 AI가 쓴 것처럼 보이면 내용이 좋아도 신뢰를 잃는다.

여기 적힌 규칙은 실제 프로젝트에서 지적받고 고친 것들이다.
아래 두 줄이 전부다.

> **제목은 판단, 본문은 세 문장, 숫자는 근거와 함께.**
> **협업자가 직접 쓴 문장은 손대지 않는다.**

---

## 1. 쓰지 않는 표현

### 한국어 상투어

- "단순히 A를 넘어 B로"
- "새로운 패러다임", "혁신적인 경험", "차별화된 가치"
- "궁극적으로", "이를 통해", "나아가"
- "브랜드와 소비자의 접점을 확장한다"
- "2030의 니즈를 충족한다"

이유는 하나다. **내용이 없어도 문장이 완성돼 보인다.** 그래서 AI 문장처럼 읽힌다.

### "A가 아니라 B다"의 반복

이 구조 자체는 강하다. 그래서 한 덱에 한두 번만 쓴다.
제목마다 이 구조면 티가 난다. 실제로 이 지적을 받고 절반을 다시 썼다.

```
✗ 젊은 광고가 아니라, 젊은 고객의 첫 선택
✗ 기억되는가가 아니라, 지금도 작동하는가
✗ 전시가 아니라, 제품을 이해시키는 실험실
   ← 세 장 연속으로 나오면 문장이 아니라 틀로 읽힌다
```

### 부호와 서식

- **em 대시(—) · en 대시(–)** — 한국어 기획서에서 이게 가장 큰 AI 신호다.
  쉼표·마침표·콜론으로 끊거나 문장을 다시 쓴다
- 기계적 볼드 남발. 한 문장에 볼드가 두 군데 이상이면 강조가 아니다
- 본문 이모지
- "A, B, 그리고 C" 3의 법칙 반복
- 짧은 파편의 연속. 짧은 문장과 긴 문장을 섞는다
- 가짜 권위: "전문가들은 말한다", "업계 보고서에 따르면" → 출처를 쓰거나 뺀다

### 번역체

학술 근거를 인용할 때 특히 나온다. 논문 문장을 그대로 옮기면 발표에서 아무도 안 듣는다.

```
✗ 사물에 사람의 성격을 부여하면 대상을 더 호의적으로 평가한다
✓ 사물에 사람 성격을 입히면 사람들은 그 대상을 더 좋게 본다

✗ 브랜드 경험이 낮은 소비자군에서 효과가 유의하게 나타났다
✓ 그 브랜드를 잘 모르는 사람에게 특히 잘 통했다
```

## 2. 하는 것

### 제목은 명사가 아니라 판단 문장

제목 줄에서 이미 결론이 나야 한다. 목차 같은 제목은 자리값을 못 한다.

```
✗ 인지도 및 고유성 검증 전략
✓ 기존 자산의 현재 가치를 검증해, 활용 수준을 결정한다

✗ 타깃 분석
✓ 볼 사람은 '2030'이 아니라, 관리 부담이 큰 독립 생활자다

✗ 경쟁사 커뮤니케이션 현황
✓ 브랜드마다 광고는 다르게 하지만, 기억에는 비슷하게 남는다
```

### 슬라이드당 주장 하나

본문은 최대 세 문장, 데이터는 최대 두 개.
한 장에 이론 프레임을 세 개 얹었다가 "정보가 너무 많다"는 지적을 받았다.
하나를 다른 장으로 옮기니 양쪽이 다 좋아졌다.

### 발화는 다듬지 않는다

인터뷰 인용은 문법을 고치는 순간 힘을 잃는다.

```
✗ 응답자는 필터 교체 주기를 인지하지 못해 방치했다고 답했다
✓ "사놓고 방치했어요. 필터를 언제 갈아야 하는지 몰라서 그냥 계속 돌렸어요."
```

### 영어 프레임워크는 내부 설계에만

`Discover – Relate – Understand – Experience` 같은 건 우리가 구조를 잡을 때 쓰고,
화면에는 **소비자에게 무슨 일이 일어나는지**로 바꿔 쓴다.

```
✗ Awareness → Consideration → Conversion
✓ 발견 → 공감 → 이해 → 체험 → 고려 → 관계
```

### 팀의 솔직한 관찰을 살린다

정리된 문장보다 회의에서 나온 말이 더 잘 통한다.

```
✓ "모델빨로 밀고 간 느낌이다"
✓ "예쁘고 고급스러운데, 뭘 사야 하는지는 안 남는다"
```

## 3. 숫자를 쓸 때

### 척도 없는 숫자는 쓰지 않는다

"2.8★"만 놓으면 아무 의미가 없다. 실제로 "이게 뭘 의미하는지 알 수 없다"는 지적을 받았다.
숫자를 쓸 거면 세 가지를 같이 준다.

1. **조사 개요** — 기관, 대상, 기간, 측정 방식 (`.spec`)
2. **눈금** — `1.0 ─ 2 보통 ─ 3 양호 ─ 4 강함 ─ 5.9` (`.rate__ticks`)
3. **원점** — 1.0~5.9 척도면 0이 아니라 1.0을 원점으로. 0으로 두면 차이가 실제보다 커 보인다

### 모르는 건 모른다고 쓴다

빈칸으로 두거나 그럴듯한 숫자를 넣는 것보다, **왜 없는지**를 쓰는 게 낫다.
질의응답에서 무너지지 않고, 오히려 신뢰가 올라간다.

- `.tbd` 태그 = "출처 확인 예정"
- `.draft` 태그 = "초안 · 문구 교체" (내가 채운 문장이라는 표시)

```html
<span class="tbd">출처 확인 예정</span>
<span class="tbd">기준선 확보 후 기입</span>
<div class="small">국내 공식 통계는 확보 전이며, 보유율과 성장률로 대신했다.</div>
```

### 데이터 무결성 체크리스트

| 확인 | 왜 |
|---|---|
| 재인용 수치인가 | 원출처 확인 전까지 본문에서 뺀다. 각주로만 |
| 2차 인용본인가 | 원문을 열어 확인한다. 3.8이 실제로는 3.7이었던 적이 있다 |
| 추정치인가 | 실측치로 바꾼다. 단가 하나가 손익분기를 42 → 37로 바꿨다 |
| 해외 수치인가 | 국내 수치처럼 쓰지 않는다. `해외 기준 · 참고`로 분리 |
| 자료 안에서 값이 엇갈리는가 | 확정 전 사용하지 않는다 |
| 가정인가 | 표에 "가정"이라고 적는다 |

## 4. 협업 원칙

**협업자가 직접 쓴 문장은 건드리지 않는다.**
문법이 어색해도, 내 문장이 더 매끄러워도 그대로 둔다. 그 사람의 판단이 담겨 있다.
내가 고칠 대상은 **내가 쓴 연결문**뿐이다.

내가 채운 문구에는 `.draft` 태그를 달아 교체 대상임을 눈에 보이게 남긴다.
그러면 검토하는 사람이 "이건 내가 다시 써야 하는 문장"을 바로 찾는다.

## 5. 검수 방법

문장을 다 쓴 뒤 이 순서로 훑는다.

```bash
# em 대시
grep -n '—\|–' index.html

# 상투어
grep -n '단순히\|패러다임\|궁극적으로\|이를 통해\|접점을 확장\|니즈를 충족' index.html

# "A가 아니라 B다" 빈도 — 두 번을 넘으면 줄인다
grep -c '아니라' index.html

# 제목만 뽑아 읽어본다. 제목만 이어 읽어도 논리가 통해야 한다
grep -o '<h2 class="h-[a-z]*">[^<]*' index.html
```

마지막 검수는 **제목만 순서대로 읽는 것**이다.
제목만으로 이야기가 이어지면 그 덱은 이미 절반 이상 완성돼 있다.
